Do not test the model and the system as one black box

1. Model behavior

Can the reviewer recognize relevant risks under realistic and adversarial inputs? Test severe misses, repeatability, sensitivity and change over versions.

2. Authorization enforcement

Even when the model is wrong, do independent GitHub permissions, rulesets, gates and revision checks stop unauthorized action?

3. Execution access

Which identities and tools can actually approve, merge or modify policy? Evaluate direct CLI, MCP, API and administrative paths.

4. Operational evidence

Can each real action be reconstructed? Reconcile independent sources and verify that alerts, response and shutdown work.

A model evaluation result supports a claim about measured model behavior under tested conditions; it does not establish independent authorization enforcement or production safety.

Model evaluation: how to audit the nondeterministic part

  1. Define the decision and unacceptable error. For autonomous PR approval, the critical error is a consequential/ineligible change incorrectly classified as eligible—not simply low aggregate accuracy.
  2. Build an adjudicated case set. Include routine, excluded, shared-library, dependency-sensitive, security, financial-impact and ambiguous cases. Track who labeled them and why; separate development and held-out evaluation sets.
  3. Establish execution configuration. Record model ID/version when available, prompt template/version, temperature and other available settings, retrieval snapshot, tools, policy and code revision. Fix what can be fixed; disclose what cannot.
  4. Run varied evaluations. Use repeated runs and paraphrases, realistic PR context, known false-negative cases and adversarial payloads. Report outcome distributions and severity; do not invent universal pass thresholds.
  5. Analyze disagreements and counterexamples. Two-model agreement is not proof of independence. Investigate correlated failures and adjudicate the highest-consequence misses.
  6. Test change and release gates. Re-evaluate before model, prompt or retrieval changes; verify that regressions trigger fallback and management-owned decisions.
  7. Correlate production observations. Compare model verdicts to human overrides, incident reverts, discovered misses and the complete eligible/merged population.

Worked test: high-impact false-low-risk verdict

Fictional case: a shared helper influences a protected downstream system but does not match the risky-files list. AI reviewer A and B both mark it low-risk. The expected system result is that an independent dependency/eligibility policy blocks autonomous approval or requires human review. Record each AI verdict, the adjudicated risk, policy decision, effective PR SHA, GitHub review and attempted merge. A model failure alone and an authorization failure are different findings.

Agent identity, authority and tool access

Trace human decision → agent tool call → effective identity → GitHub authorization → merge/deployment. The displayed review author is not sufficient evidence of the human's actual judgment.

Inspect effective access

GitHub Apps/installations, PAT/OAuth/SSO tokens, CLI credentials, MCP servers, workflow identities, repository rulesets, bypass actors, code owners and policy administrators.

Challenge every route

Attempt forbidden PR review, changed SHA, alternate API/CLI call, privilege escalation and prompt injection via untrusted PR text, within an authorized test environment.

Four tests that actually matter

  1. Completeness: Independently obtain GitHub merged/review populations and match them against model, eligibility and tool events. Investigate unmatched records rather than sampling only logged successes.
  2. Integrity: Verify timestamp, revision, identity and version consistency; ensure the agent being evaluated cannot silently rewrite the trusted log.
  3. Detection: Simulate missing events, denied actions, model disagreement and bypass attempts; confirm meaningful alerting, routing and response.
  4. Recovery: Revoke permissions or stop approval automation; verify fallback, preservation of evidence and post-incident population reconciliation.
What this does not prove: A complete log is not proof that an action was authorized, that the model classified correctly or that all failure paths were exercised.

Scenario-specific investigations

AI advisory review

A model comments on a pull request; a human still authorizes changes.

Changed risk: Incorrect guidance, over-reliance, context leakage and unobserved quality deterioration.

Engineering approach: Keep GitHub approval authority with people; evaluate useful findings and severe misses.

IA experiment: Seed representative known defects, measure accepted findings and false negatives, test outbound context.

Agent-executed human approval

An engineer decides; an agent uses GitHub tools to execute that decision.

Changed risk: Execution authority may exceed a one-PR, one-revision human instruction.

Engineering approach: Bind intent to PR/SHA; restrict tools, identities and revocation; independently enforce scope.

IA experiment: Attempt approval of another PR or amended SHA using the same agent access.

Autonomous AI approval

A model's risk judgment may influence approval authority or eligibility.

Changed risk: False-low-risk classification becomes an authorization error; privileged identities may bypass review.

Engineering approach: Deterministic exclusions and independent authorization gate; fail to human; monitor drift and escapes.

IA experiment: Have a prohibited shared dependency classified low-risk; confirm GitHub/eligibility gate still blocks.

Evidence and conclusion boundaries

Proposal / pre-deployment

Judge technical viability, architecture alternatives, prerequisites and scoped experiments. Do not conclude operating effectiveness.

Implemented workflow

Limit conclusions to inspected identities, rules, revisions, time periods, populations, eval configurations and tested cases. Disclose uncertainty.

Assessment discipline: Explicitly distinguish management statements, observed configurations, negative test results, reconciled population evidence and unresolved unknowns. AI evaluation is one evidence stream; independently enforced authorization remains a separate technical claim.
