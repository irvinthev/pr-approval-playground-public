04 / OPERATE · Monitoring & Operations

A PR changed after approval. Would we know?

Observability tells us that something happened. Reconciliation tells us whether that action matched authority for the relevant revision and whether the same change reached production.

The incident

Revision A receives approval. Revision B arrives later. The old approval is still a historical record, but the delivery system must resolve whether it remains valid.

An unmatched event could be a broken rule, an authorized exception, or incomplete evidence. Investigate before concluding.

Where does an operating signal become a decision?

Follow four phases of a fictional stale-approval incident. Each phase changes what Engineering knows and can responsibly do.

DECISION TAKEAWAY

Dashboards are not enough. Operational confidence requires independently scoped event populations, tested join logic, response ownership and a credible path to contain and recover.

TRACE THE REAL PATH

The change-to-production chain is the unit of reconciliation.

A useful signal connects the approved decision or human instruction to the executing identity, GitHub merge event, CI/build provenance, released artifact and deployment. Not every commit hash should match naively: squash, rebase and merge-queue mappings need explicit treatment. For other AI agents, reconstruct instructions, tool actions, changes and production effects with equivalent rigor.
