One change, from pull request to production

The complete example path is visible here. Open the pipeline only when you want to inspect decisions and scenarios.

1. Pull request

Identify the proposed change and exact revision.

2. Policy & dependency checks

Check scope, affected services, financial relevance, and mandatory exclusions.

3. Code review

Review correctness, security, and quality through applicable automated and human review.

4. AI risk evaluation

Evaluate eligible changes; disagreement or uncertainty routes to a human.

5. Authorization

Enforce independent, revision-bound approval or human escalation.

6. Merge

Verify required checks and branch protections before merging.

7. Deploy

Validate the released artifact matches the authorized change.

8. Monitor

Observe outcomes, exceptions, and rollback or shutdown signals.

Illustrative sequence, not evidence of a deployed control. Code review, AI risk classification, and authorization are distinct activities.
