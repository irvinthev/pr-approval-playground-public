Example safeguards by approval model

Illustrative design patterns, universal requirements, or an assessment of operating effectiveness. Apply only where relevant.

1 · Human decides and submits

  • Defined reviewers and applicable ownership routing, including CODEOWNERS where appropriate
  • Effective branch protections, review requirements and stale-review treatment
  • Traceable GitHub reviewer, PR revision, and merge outcome

Why: The merge gate should reflect the intended reviewer and code revision. CODEOWNERS is optional unless applicable rules require it.

GitHub: CODEOWNERS · Protected branches

2 · Human decides, agent submits

  • Explicit human instruction and the particular PR/revision authorized
  • Bounded CLI, MCP, App and credential permissions; independently enforced merge rules
  • Correlation of human decision, agent action, GitHub review and revision

Why: A tool permission prompt is not identical to GitHub authorization, and submitting a review does not prove the human made that decision.

Claude: permissions · GitHub CLI review

3 · AI decides and submits

  • Deterministic scope and exclusions; explicit automated decision policy
  • Restricted execution identity and revision-bound approval/merge gates
  • Performance monitoring, reconciliation, incident response and automation suspension

Why: If AI independently decides, its authority and failure modes differ from merely executing a human decision. Guardrails must be independently effective.

GitHub: rulesets · OWASP: agentic threats
