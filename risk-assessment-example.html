Worked example · Fictional / not a system assessment

Human decides. Agent submits. What must be true?

A hypothetical engineer makes an explicit approval decision for a stacked pull request and instructs an agent to submit the GitHub review. The agent executes the instruction; it does not independently decide whether to approve.

Conditional engineering recommendation

Explore a narrow, non-critical pilot. Do not rely on agent-submitted approval until enforcement is established.

The proposed separation of human judgment from agent execution could reduce repetitive work. But a recorded human instruction is not enough if the agent can approve a different revision or use credentials that bypass the intended approval route.

How could it actually fail?

An engineer authorizes commit A; the PR changes to commit B. An agent submits the earlier instruction, and effective GitHub rules allow approval of B to count toward a protected merge. If the merge/release path also allows it, unreviewed code could reach production.

Strongest competing explanation

Effective GitHub rules may already reject stale reviews, prevent the agent identity from satisfying required approvals, and restrict bypass. If so, the most serious failure path is constrained. Those settings and their behavior have not been established for this fictional case.

Most important safeguards

  • Human authorization bound to an exact revision.
  • Agent identity and credentials cannot independently authorize or bypass.
  • Protected merge rejects stale or unauthorized approvals.
  • Reconcile instructions, GitHub events, merges and deployed revisions.

Implementation status: Unknown for every safeguard.

Simpler alternative

Use AI to prepare review findings and a prioritized stacked-PR queue, then have the engineer approve directly in GitHub. This preserves native attribution with less agent authority. The alternative may deliver most of the productivity benefit with lower operating complexity.

What could change the recommendation?

Decision-changing test: With the real agent identity, token scopes and effective repository rules, can a reviewer instruction for commit A cause commit B to receive a qualifying approval or merge without fresh human authorization? Test both the normal route and the effective bypass paths. If an unauthorized merge is possible, do not enable the route. If independently prevented and reconstructable, a bounded pilot becomes more credible.
